# Portfolio visitor test

This is a prepared protocol, not a study that has already been run.

## Participants and setup

Recruit five people similar to prospective clients or collaborators. Include phone users and at least one person who normally navigates with a keyboard or reduced motion. Five is a practical formative sample; it is not statistically representative. Obtain permission before recording their screen or comments.

Use the published site in each person's normal browser. Do not explain the layout in advance. Do not ask them to send an email during the test.

## Tasks

1. Tell me whose site this is and what they do.
2. Pick a design study that interests you. Explain what is being explored and who created the featured artwork.
3. Find how you would contact Endi. Open the contact action without sending a message.
4. Return to the study you were just reading.
5. If the animation is distracting, show me how you would reduce it or skip the intro.

## Record

For each task record completion, time, wrong turns, hesitation, and the person's own words. Treat 30 seconds to identify specialty/find contact as an internal investigation threshold, not an industry benchmark or a claimed current result. Ask whether the distinction between concept design and third-party artwork is clear.

## Manual device/accessibility checklist

- iOS Safari and Android Chrome on physical mid-range devices.
- Keyboard order, visible focus and browser Back/Forward behaviour.
- 200% browser/text zoom; reflow at 320 CSS pixels; both orientations.
- System reduced motion switched while the page is already open.
- No WebGL, interrupted image loading, and lost WebGL context.
- Accurate artwork credits and working original downloads.
- Direct project URLs on GitHub Pages return 200; an unknown route returns 404.

The automated Chromium suite covers several related behaviours, but it does not substitute for the physical-device and human checks above.
